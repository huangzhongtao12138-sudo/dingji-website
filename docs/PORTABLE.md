# 跨电脑携带与 AI 接手

2026-10-10，按用户要求，将当前官网整理为桌面「网站」文件夹中的完整可携带副本。

## 文件夹结构

```text
网站/
  先读我.md                 使用方法与发布边界
  给GPT的接手说明.txt       可复制到新对话的提示词
  AGENTS.md                AI 工作入口
  dingji-website/           完整官网仓库，包含隐藏的 .git 历史
    outputs/               生产页面、样式、脚本、图片、证照和 3D 场景
    docs/                  公司资料、历史决策和本说明
  外部资源备份/            外链视频、字体与固定版本 Spline 查看器
  tools/                   跨平台预览与迁移完整性校验工具
  迁移清单.json             打包时每个文件的大小和 SHA-256
  迁移验证报告.md           本次复制与检查结果
```

整个「网站」文件夹可以复制到 Windows、macOS 或 Linux。项目代码使用相对路径，不依赖原电脑的用户名、工作目录或旧聊天记录。复制时保留隐藏的 `.git` 文件夹；建议压缩整个文件夹后传输，避免遗漏隐藏文件。

## 在新电脑编辑

1. 解压或复制整个「网站」文件夹。
2. 在具备本地文件读写能力的 AI 开发工具中打开此文件夹，提供「给GPT的接手说明.txt」。只支持聊天或上传的工具需要显式上传相关文件，不能自动访问本地文件夹；上传大小限制以所用工具为准。
3. AI 先阅读根目录 `AGENTS.md`、仓库 `AGENTS.md`、`docs/PROJECT_MEMORY.md`、`docs/DECISIONS.md` 和待修改的页面。实际编辑 `dingji-website/outputs/`，不编辑外部资源备份作为生产入口。
4. 预览需要 Python 3，版本管理与发布需要 Git。静态页面编辑不需要 Node.js、npm 或构建步骤。
5. 在「网站」目录运行 `python3 tools/preview.py`；Windows 可用 `py -3 tools/preview.py`。浏览器访问 `http://127.0.0.1:8000/`，按 Ctrl+C 停止。端口被占用可加 `--port 8001`。
6. 新复制后运行 `python3 tools/verify_transfer.py`（Windows 用 `py -3`），核对迁移基线。开始编辑或执行 Git 操作后，文件变化是正常的；此校验不用于判断新版本内容是否正确。

## 版本与发布

迁移时的基准提交为 `9b4fb77bdd757b332ffdc21188a9930a126fb7de`。已通过 GitHub API 核对，该提交与 2026-10-10 查询时的远端 `main` 一致。初次打包时新增的迁移说明随文件夹携带；2026-10-10 后续搜索修复将这些说明一起纳入版本管理。当前版本及未提交状态始终以 Git 检查结果为准。

原电脑工作目录与桌面副本是两个独立目录，不会自动同步。后续一次只在选定的一份工作副本中编辑，并通过 Git 同步；再次迁移应重新复制最新文件夹，不要覆盖另一台电脑上的未提交改动。

上线前在 `dingji-website/` 检查 `git status` 和 `git diff`，保留本地改动；登录有该仓库权限的 GitHub 账号，获取远端更新并按实际情况合并，完成验证后再提交和推送。`main` 推送会触发现有 Vercel 正式部署，需要按当前用户授权范围处理，并提前说明会更新线上网站。

账号登录状态、密码、令牌、DNS 控制权、Vercel 后台设置和旧聊天记录不属于源码文件，不能靠复制文件夹迁移。本包不包含账号凭据。部署所需的已知设置已写入 `DEPLOYMENT.md` 和项目资料库。
